Vector/layout/quantization의 물리 실행원은 C1, TCU GEMM은 C1, naive GEMM은 C3, improved GEMM은 C4인 현재 composition 규칙을 사용한다. 아래 절대 latency는 prepared `total.csv`의 값을 초로 표현했다. `aggregation_kind=average_tpot`인 decode 값은 prepare 시점에서 이미 128로 나눴으므로 **추가로 128로 나누지 않는다**.

그림의 TTFT/TPOT은 개별 kernel의 FPGA cycle latency에 층별 호출 수를 적용해 합성한 모델 latency다. Host 실행과 전체 inference wall-clock 시간을 직접 측정한 값으로 해석하지 않는다. Prefill의 L은 입력 prompt 길이, decode의 L은 초기 KV-cache 길이이며, decode에서는 출력 스텝에 따라 실제 cache 길이가 증가한다.

절대 energy는 각 모델의 `composed.csv`를 청크로 읽고 `fpga_cycle × calls_per_forward × fpga_period_s × power_dynamic_avg_w × pure_dequant_scale`를 합산한 뒤 위 token 수로 나눠 계산했다. 각 지표의 192개 후보 행에 대해 latency와 energy를 prepared CSV의 relative total과 상대 오차 1e-9 이내에서 대조했다.

## 5. Stacked bar의 모든 segment 값

아래 셀의 숫자는 **같은 workload의 C4 total로 나눈 relative segment 높이**이다. 셀 내부 숫자의 합은 4절의 해당 후보 R값과 일치한다(표시 반올림 오차 제외). 절대 segment 값은 `relative segment × 4절의 C4 absolute total`로 복원할 수 있다.

GEMM-only 그림의 실제 묶음은 `Q/K/V/O projection`, `attention (QKᵀ, PV)`, `FFN (up/gate/down projection)` 세 개이며, 단순히linear/attention 두 그룹으로 합치지 않았다.

E2E의 layout은 C4 fused kernel과 대응 C3 기본 kernel의 차이 중 양수 부분을 kernel별로 합산한 값이다. vector segment에서는 이 layout 값을 빼므로 total은 보존된다. 개별 fused kernel의 속도 향상이 다른 kernel의 양수 layout overhead를 상쇄하지 않도록 `max(0, fused − base)`를 먼저 적용한다. Latency와 energy의 각 단위에서 독립적으로 계산한다.
