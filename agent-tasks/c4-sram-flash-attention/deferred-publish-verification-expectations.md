# Independent expectations for deferred PUBLISH response

Prepared against the frozen pre-repair source on 2026-10-24. No repair build or simulation has been launched. Root release and the author's final test request are required before execution; the passed monitor smoke is frozen under `logs/decoder_resident_progress`.

The semantic obligation is that a PUBLISH **response** follows physical commitment of the producer's earlier accepted LMEM stores. The proposed change intentionally permits request acceptance before that drain, removing published from request-ready. The existing real-LSU queued-store ordering witness must remain.

| Case | Required observation |
|---|---|
| Original physical-store fixture | Retain normal CPU data readback, withheld PUBLISH result during held physical bank, DMA source-tag classification and physical commit checks. Run original `sram_lmem_publish` without supplement macro. |
| Real LSU queued publication | Retain both warp0/1 cases: PUBLISH enters real scheduler behind the unadmitted store while accounting is empty; no result then. After store admission, count exactly one accepted PUBLISH request while bank is blocked, followed by at least32 cycles of pending response with no result. Release physical bank, require exactly one CPU commit and PUBLISH result1 plus exact64-bit readback. Keep queued_during_hold=2, input-hold>=64 aggregate, blocked-pending>=64 aggregate, commits/results/readbacks2 each. |
| Pending slot overwrite exclusion | While one publication waits, present a distinct read/tag/mask and separately a doorbell write; neither may be accepted or change saved response/register/launch state. Count handshakes, not only valid levels. After the original response completes, a successor request may proceed once. |
| Mixed read snapshot | Accept one transaction containing PUBLISH and ordinary metadata words/lanes. Change metadata through legitimate independent hardware events during physical drain; returned ordinary fields, tag and mask must reflect acceptance, PUBLISH must report1 after drain. Ordinary reads without PUBLISH remain immediate snapshots. Masked/byte-disabled PUBLISH addresses must not spuriously defer a read. |
| Response backpressure | Hold rsp_ready low across drain and at least several response-valid cycles. Require stable valid, full data, tag and mask; no overwrite/duplicate or early consume. Toggle publication state after response becomes valid through permitted producer events: completed response must remain stable. Verify same-edge response consume/new-request behavior according to final slot contract, with no dropped transaction. |
| Reset while pending | Accept PUBLISH while drain blocked, reset before response becomes valid, then release/reset-recover and require no stale response/tag or launch. A fresh read/publication must succeed. Separately reset while a valid response is backpressured. Reset cancellation does not imply clearing physical SRAM contents. |
| Same-edge CPU store admission | Exercise real accepted-store accounting with an admission coincident with publication request/release evaluation where the configured route permits it. `published` must remain false when admitted_count!=0 even if pending_count was0. If same-interface ordering precludes simultaneous request acceptance, use the permitted independent port or a focused controller input fixture and identify that limited scope explicitly. No fabricated accounting-state forces. |
| Doorbell exclusion | A doorbell presented behind deferred PUBLISH must not trigger bridge_busy acquisition or cmd_valid until its own accepted request. Once publication drains, retain existing busy/quiescent validation and same-edge GEMM/doorbell arbitration checks. |
| Structural compatibility | Before/after feature-off selected RTL identity and feature-on req_ready cone independent of lmem_published_i. Confirm response storage stays bounded: one pending bit reuses saved mask/tag/data rather than unbounded buffering. Simulation does not by itself close the FPGA combinational-loop/timing gate. |

Source basis: `hw/rtl/core/VX_sram_fusion_ctrl.sv` currently gates req_ready with publication at lines102-103, snapshots read payload at216-222, and derives same-edge bridge_busy from accepted doorbell. `hw/rtl/core/VX_mem_unit.sv:278-309` counts accepted CPU stores until physical CPU commits and includes current-edge admissions in published. Existing original test checks response withholding. `hw/unittest/sram_lmem_publish/sram_publish_upstream_tests.svh:53` currently also demands req_ready low, and its hold counter depends on req_valid staying asserted: these are obsolete request-timing expectations after the proposed repair. Replace them with actual accepted-request plus pending-response witnesses; do not remove store/commit/result ordering assertions.
