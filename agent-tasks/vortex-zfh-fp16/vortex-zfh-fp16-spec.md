# Vortex Scalar Zfh/LP64F Support Specification

Status: confirmed

## Goal

Enable native scalar IEEE FP16 instructions generated by Vortex Clang for an
RV64 Vortex target built with:

```text
-march=rv64imaf_zfh -mabi=lp64f
CONFIGS += -DEXT_D_DISABLE -DEXT_ZFH_ENABLE -DFPU_FPNEW
```

The purpose is to execute `_Float16` kernel arithmetic and conversions without
the RISC-V D extension and without falling back to software half conversion
helpers for operations covered by Zfh.

## Scope

### RTL

- Decode scalar Zfh load/store, arithmetic, fused arithmetic, conversion,
  comparison, classify, sign-injection, min/max, and move encodings that are
  relevant to compiler-generated code.
- Preserve the full RISC-V two-bit floating-point instruction format and keep
  operation modifiers such as add/sub and 32/64-bit integer selection separate
  from the floating-point format.
- Enable fpnew FP16 while keeping FP64 disabled when `EXT_D_DISABLE` is set.
- Preserve existing FP32 behavior and retain FP64 behavior for configurations
  that do not disable D.
- Ensure FP16 values follow RISC-V NaN-boxing rules in the wider floating-point
  register representation.
- Reject or leave illegal encodings undecoded when their required extension is
  disabled.

### Software integration

- Make Vortex kernel/regression compilation select `rv64imaf_zfh/lp64f` only
  when `EXT_ZFH_ENABLE` is present with the no-D configuration.
- Continue using the completed software profile under
  `/opt/vortex_profiles/rv64imaf_zfh_lp64f`.
- Add a reusable hardware configuration that includes `EXT_D_DISABLE`,
  `EXT_ZFH_ENABLE`, and `FPU_FPNEW`.
- Add a small regression kernel that forces native FP16 arithmetic and
  FP16/FP32 conversions and checks numerical results.

### Verification

- Compile inspection: prove the test kernel contains Zfh instructions and no D
  instructions, and that the linked ELF is tagged single-float ABI.
- RTL compile/unit-level check through `tools/verify_rtl.py` as selected by the
  RTL implementation agent.
- End-to-end blackbox test in a configured build directory using
  `ci/run_black.sh xrt-vcs-sim` and the FP16 configuration.
- Run at least representative FP16 add, multiply, and FP16/FP32 conversion
  cases, including negative, zero, and rounding-sensitive values.

## Expected Affected Areas

- `hw/rtl/VX_gpu_pkg.sv`
- `hw/rtl/VX_config.vh`
- `hw/rtl/core/VX_decode.sv`
- `hw/rtl/fpu/VX_fpu_fpnew.sv`
- Other FPU/LSU integration files identified by implementation analysis
- `kernel/Makefile`
- `tests/regression/common.mk` and related kernel common makefiles
- `configs/`
- A new or existing FP16-focused regression application

## Design Decisions

- fpnew is the supported scalar FP16 backend for this work. The DSP and DPI FPU
  backends are not expanded to implement Zfh.
- D remains disabled in both RTL and every software object. C/C++ `double`
  remains available through the rebuilt compiler-rt software helpers.
- The implementation uses an explicit `EXT_ZFH_ENABLE` configuration macro so
  existing no-D configurations do not silently advertise unsupported Zfh.
- Existing Vortex target-feature spelling is retained (`+vortex` for the
  installed LLVM 18 toolchain).
- The task does not change the TCU FP16 format; scalar Zfh support is a separate
  core FPU feature.

## Constraints and Assumptions

- XLEN is 64 and ABI is LP64F.
- The installed Vortex Clang 18 revision
  `c2516577cb9104f53aaef095c1c3a1d2517cec36` is used.
- The completed musl/compiler-rt profile is the software runtime source.
- RTL simulations use a configured build directory and xrt-vcs-sim for
  blackbox execution.
- Existing unrelated worktree changes must be preserved.

## Completion Criteria

The task is complete when the FP16 test compiles into native Zfh instructions,
the required RTL checks pass, the xrt-vcs-sim blackbox test passes under
`EXT_D_DISABLE`, and no linked object advertises the D extension.
