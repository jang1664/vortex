# GEMM FSM Command-Overlap Trace Plan

## Objective

Add simulation-only command lifecycle and overlap observability for the GEMM
command stream generated by `VX_gemm_fsm`. The first comparison targets the
following one-core workloads:

```text
M=4,   N=32, K=128, QBLK=32, WTRANS=0, QDIR=0
M=256, N=32, K=128, QBLK=32, WTRANS=0, QDIR=0
```

The instrumentation must answer these questions:

1. When did every FSM command enter the scheduler, start its executor, and
   complete logically?
2. How much of each command's lifetime overlapped another command class?
3. Did the next tile preload overlap the current tile's compute work?
4. Did an output DRAM store overlap useful work from a later tile, especially
   later compute or later DRAM loads?
5. Was work hidden by double buffering, or did a consumer wait for preload or
   output-buffer reuse?
6. For a chunked output store, how much time was spent running, paused behind
   high-priority loads, pending, and switching between store and load work?

This phase will not add or change a performance CSR. All new state, ports,
checks, and output will be guarded from synthesis.

## Important Workload Interpretation

The default DMA tile height is 128. With the fixed `N=32`, `K=128` geometry:

| Workload | DMA tiles | Output-store form | Expected inter-tile opportunity |
|---|---:|---|---|
| `M=4` | 1 | 256-byte partial-channel fallback, non-chunkable | No later tile exists; later-tile overlap must be zero |
| `M=256` | 2 | 8192-byte all-channel burst store per tile, chunkable | Tile 1 can be prefetched during tile 0 work; store 0 can overlap tile 1 compute |

`M=256` has only two DMA tiles. Tile 1 is normally loaded by the initial
double-buffer preload before tile 0 reaches its output store. Therefore,
`store(tile 0) versus load(tile 2)` cannot occur in this geometry because tile
2 does not exist. A zero store-versus-next-load result at `M=256` is not by
itself a failure.

To test the exact recently added store-to-later-load scheduling path, add this
diagnostic control workload after the requested two cases:

```text
M=384, N=32, K=128, QBLK=32, WTRANS=0, QDIR=0
```

It has three DMA tiles and can expose output store 0, the tile 2 preload, and
tile 1 compute in the same scheduling window. The `M=4` and `M=256` results
remain the required primary report.

## Measurement Semantics

### Three lifecycle boundaries

Every command will have three timestamps. They must not be conflated:

```text
emit_cycle   : VX_gemm_fsm command is accepted into its child FIFO
issue_cycle  : the child executor accepts the command
done_cycle   : the child reports the command's architectural completion
```

Derived durations use half-open intervals:

```text
queue_cycles   = issue_cycle - emit_cycle
service_cycles = done_cycle  - issue_cycle
total_cycles   = done_cycle  - emit_cycle
active interval = [issue_cycle, done_cycle)
```

For DMA commands, `issue_cycle` is the tagged `cmd_valid && cmd_ready`
acceptance into `VX_gemm_tmem_dma_ctrl`. The interval can include time spent in
the pending queue or a paused store context. It is therefore a logical
inflight interval, not proof that two descriptors execute simultaneously.

### Logical overlap versus DMA-engine execution

The design has one descriptor-execution context. A paused output store and a
selected input load can be logically inflight together, but their descriptors
must not execute on the DMA engine in the same cycle.

The report will use separate terms:

- `logical_overlap_cycles`: intersection of command issue-to-done intervals;
- `descriptor_active_cycles`: cycles in which that DMA command owns the active
  descriptor;
- `pending_cycles`: accepted but not selected;
- `paused_cycles`: an unfinished store context exists while another command is
  selected or executes;
- `switch_cycles`: store-chunk completion to selected-load descriptor issue.

The summary must never label logical inflight overlap as simultaneous DMA
bandwidth use. Store/load descriptor-active overlap should remain zero by
construction and will be asserted.

### Command classes

Classify the existing unified command without changing
`gemm_unified_cmd_t`:

| Class | Decode |
|---|---|
| `DRAM_INPUT_LOAD` | `OP_DMA_LD`, `rd=0` |
| `DRAM_WEIGHT_LOAD` | `OP_DMA_LD`, `rd=1` |
| `DRAM_SCALE_LOAD` | `OP_DMA_LD`, `rd=2` |
| `DRAM_ZP_LOAD` | `OP_DMA_LD`, `rd=3` |
| `DRAM_OUTPUT_STORE` | `OP_DMA_ST`, `rd=4` |
| `MXU_WEIGHT_LOAD` | `OP_W_LDMA_MXU` |
| `MXU_SCALE_LOAD` / `MXU_ZP_LOAD` | `OP_SZ_LDMA_MXU`, disambiguated by FSM state |
| `COMPUTE_ARM` | `OP_I_LDMA_ARM` |
| `ACCUM_TO_LMEM` | `OP_O_ACC2LMEM` |

The command-active `COMPUTE_ARM` interval and the exact
`!gemm_unit_v2_if.pipeline_empty` predicate will both be recorded. The former
is a command lifetime; the latter is the cycle-exact compute-pipeline activity
used for overlap percentages.

## Per-Command Record

Assign a monotonically increasing simulation-only `cmd_uid` at FSM-to-child
FIFO acceptance. Each completed record will contain:

```text
job sequence and entry ID
cmd_uid
command class, opcode, FSM state, target child
linear tile ID and nt/mt/kt coordinates
MXU nt/kt coordinates where applicable
tile buffer, MXU buffer, accumulator group, generation
size, source address, destination address
wait metadata and notify metadata
DMA tag where applicable
emit_cycle, issue_cycle, done_cycle
queue_cycles, dependency_blocked_cycles, executor_blocked_cycles
service_cycles, total_cycles
overlap_any_cycles
overlap_by_class[class]
overlap_compute_pipeline_cycles
overlap_later_tile_load_cycles
overlap_later_tile_compute_cycles
```

The FSM already has the normalized tile and buffer context at emission time.
Expose that context as a simulation-only metadata output rather than trying to
reconstruct every coordinate later from overloaded `rs1`, `rs2`, and `rd`
debug fields.

## Tile-Level Double-Buffer Metrics

For every tile `t`, dump the following derived records where the referenced
command exists:

```text
preload(t+1) intersect compute(t)
output_store(t) intersect compute(t+1)
output_store(t) intersect DRAM_load(t+1)
output_store(t) intersect DRAM_load(any later tile)
ACCUM_TO_LMEM(t) intersect output_store(t-1)
```

Also calculate:

```text
preload_hidden_cycles
preload_tail_cycles = max(0, preload_done(t+1) - compute_done(t))
tile_ready_slack    = compute_start(t+1) - preload_done(t+1)
store_hidden_cycles
store_tail_cycles  = max(0, store_done(t) - compute_done(t+1))
```

Positive `tile_ready_slack` means the preload completed before the next tile
needed it. A positive `preload_tail_cycles` value identifies an exposed
double-buffering miss. For the final tile, report final store drain separately
instead of treating the lack of a later tile as a miss.

## Implementation Plan

### 1. Add a dedicated simulation macro

Use `DBG_TRACE_GEMM_CMD_PERF` for this instrumentation. Guard every new
declaration and connection with both:

```systemverilog
`ifndef SYNTHESIS
`ifdef DBG_TRACE_GEMM_CMD_PERF
...
`endif
`endif
```

Do not make `PERF_ENABLE` a prerequisite. The feature must compile and run
with all performance CSR classes disabled.

### 2. Capture normalized FSM metadata

In `VX_gemm_fsm.sv`:

- retain the existing `GEMM_FSM_CMD_ISSUE` event;
- add a simulation-only metadata bundle beside `out_cmd_d` containing tile,
  MXU, buffer, accumulator-group, and phase information;
- drive one metadata-valid pulse on exactly
  `out_start_d && state_child_ready`;
- add the metadata fields to the structured issue trace;
- do not add fields to `gemm_unified_cmd_t` and do not change a synthesized
  interface width.

The metadata can use a simulation-only output port from `VX_gemm_fsm` to
`VX_gemm_ctrl`. Conditional-port lint must be checked with the macro enabled,
disabled, and with `SYNTHESIS` defined.

### 3. Build the central lifecycle ledger

In `VX_gemm_ctrl.sv`:

- assign `cmd_uid` on `gemm_fsm_if.ctrl.start`;
- create simulation-only metadata FIFOs that mirror all five functional child
  FIFOs using the exact functional push/pop signals;
- assert that each debug FIFO remains aligned with its functional FIFO;
- record `emit_cycle` on push;
- record `issue_cycle` on `child_issue_fire_v[child]`;
- retain one active UID for each in-order non-DMA child;
- retain one active UID per DMA tag for the tagged DMA child;
- record `done_cycle` from `child_completion_pop_v` and DMA `done_tag`;
- count dependency-blocked head cycles separately from executor/inflight
  blocked cycles;
- sample the active command set every cycle and accumulate per-command class
  intersections;
- assert exactly one issue and one completion per UID.

Use a fixed simulation-only record capacity with an overflow assertion. Start
with `DBG_GEMM_CMD_MAX=4096`, but make it an overrideable parameter or macro so
larger diagnostic workloads fail explicitly rather than truncate silently.

### 4. Connect the exact compute predicate

In `VX_gemm_node.sv`, connect
`!gemm_unit_v2_if.pipeline_empty` to a simulation-only input on
`VX_gemm_ctrl`. This follows the existing scheduler-observability connection
to `VX_gemm_tmem_dma_ctrl` and does not depend on `PERF_ENABLE`.

The central ledger will accumulate:

```text
compute_pipeline_active_cycles
each command intersect compute_pipeline_active
DRAM load intersect compute_pipeline_active
output store logical lifetime intersect compute_pipeline_active
```

### 5. Extend per-DMA-command scheduler accounting

In `VX_gemm_tmem_dma_ctrl.sv`, extend the existing simulation-only scheduler
records without changing scheduling behavior:

- assign an accept serial number to distinguish tag reuse;
- record tag, opcode, accept time, first-select time, first-descriptor time,
  logical-complete time, chunkable/bypass mode, and chunk count;
- accumulate pending, descriptor-active, and paused-store cycles;
- dump one record per logical DMA command when the path returns to final idle;
- retain the existing aggregate `TMEM_DMA_SCHED_PERF` marker;
- assert that load and store descriptor-active predicates are mutually
  exclusive.

Controller and DMA records are joined by DMA tag plus the common acceptance
timestamp. A structured controller `cmd_uid`/tag mapping event will make this
join explicit even after tag reuse.

### 6. Dump once per GEMM invocation

Trigger the central dump from `VX_gemm_ctrl.invocation_complete`, where the
FSM is idle and all child queues and inflight records are drained. This is more
reliable than a SystemVerilog `final` block and supports multiple jobs in one
simulation.

Emit machine-parseable one-line markers:

```text
GEMM_CMD_PERF_SUMMARY
GEMM_CMD_CLASS_SUMMARY
GEMM_CMD_TIMELINE
GEMM_CMD_OVERLAP_PAIR
GEMM_TILE_OVERLAP
TMEM_DMA_CMD_PERF
```

Example shape:

```text
GEMM_CMD_TIMELINE | {job=0, uid=17, class=DRAM_OUTPUT_STORE,
tile=0, emit=810, issue=826, done=1041, queue=16, service=215,
overlap_compute=173, overlap_later_load=41}
```

The final summary will include record counts, maximum concurrent logical
commands, active-class-mask occupancy, incomplete-record count, and accounting
invariants. Human-readable percentages are useful, but raw cycle numerators
and denominators are mandatory.

### 7. Add an offline summarizer

Add a small parser under `tools/` or beside the plan's eventual test support
that reads the structured markers and emits:

- one CSV row per command;
- one CSV row per selected command pair;
- one tile-level Markdown comparison table;
- one workload-level summary for `M=4`, `M=256`, and optional `M=384`.

The parser must not require FSDB. FSDB remains optional for investigating a
counter discrepancy.

## Required Invariants

The simulation must fail rather than print misleading data when any invariant
is violated:

1. Every emitted UID is issued and completed exactly once before invocation
   completion.
2. `emit_cycle <= issue_cycle <= done_cycle`.
3. Debug FIFO push/pop order matches the corresponding functional child FIFO.
4. A non-DMA child never has more than one active UID.
5. A DMA tag is not remapped until its prior UID completes, and same-cycle tag
   reuse remains forbidden.
6. Per-command overlap never exceeds that command's service duration.
7. Pair overlap is symmetric and no larger than either interval.
8. Store and load descriptor-active predicates never overlap on the single DMA
   execution context.
9. Final dump has zero incomplete records and zero active debug entries.
10. Instrumentation enabled versus disabled produces identical numerical
    output and identical architectural command/completion counts.

## Verification Plan

### Static compilation

Compile/lint these configurations:

1. no debug macro;
2. `DBG_TRACE_GEMM_CMD_PERF` enabled;
3. `DBG_TRACE_GEMM_CMD_PERF` plus existing `DBG_TRACE_GEMM` and
   `DBG_TRACE_GEMM_FSM`;
4. `SYNTHESIS` defined.

The synthesis configuration must have no new ports, state, memories, or
warnings from this feature.

### Directed unit tests

Extend `gemm_fsm` and `gemm_ctrl` VCS tests to check:

- command class and normalized tile metadata for each opcode/state;
- UID preservation through each child FIFO;
- simultaneous activity in different children;
- out-of-order DMA completion and tag reuse;
- exact interval and pair-overlap arithmetic on a synthetic schedule;
- final dump only after full drain;
- zero incomplete records.

Extend the scheduler test to check per-tag/accept-serial pending, paused,
descriptor-active, chunk, and completion accounting.

### XRT-VCS workload runs

Use the configured build directory and source the established GEMM hardware
configuration before every run. Execute through `ci/run_black.sh xrt-vcs-sim`
with:

```text
-DDBG_TRACE_GEMM_CMD_PERF
-DDBG_TRACE_GEMM
-DDBG_TRACE_GEMM_FSM
-DDISABLE_FSDB
```

Run the required `M=4` and `M=256` cases first, then `M=384` as the direct
store-to-later-load control. All runs must pass numerical comparison.

### Expected interpretation checks

For `M=4`:

- exactly one DMA tile;
- output store is non-chunkable/bypass;
- no later-tile load or compute overlap;
- no store-to-load switch;
- the report still shows within-tile command concurrency and final store tail.

For `M=256`:

- exactly two DMA tiles;
- tile 1 preload versus tile 0 compute is measured;
- output store 0 versus tile 1 compute is measured;
- output store 0 versus tile 2 load is reported as not applicable/zero because
  tile 2 does not exist;
- both stores are chunkable for the fixed geometry;
- final store drain is separated from steady-state overlap.

For the optional `M=384` control:

- at least three DMA tiles;
- output store 0 and tile 2 load have a positive logical inflight overlap with
  the default eight-beat chunk size;
- the scheduler reports at least one store-to-load switch;
- store/load descriptor-active overlap remains zero;
- later-load and compute overlap is reported independently.

## Deliverables

1. Simulation-only RTL instrumentation in `VX_gemm_fsm.sv`,
   `VX_gemm_ctrl.sv`, `VX_gemm_node.sv`, and
   `VX_gemm_tmem_dma_ctrl.sv`.
2. Structured end-of-invocation trace markers and assertions.
3. VCS directed-test updates for lifecycle and overlap accounting.
4. A log summarizer producing per-command CSV and tile/workload Markdown.
5. Numerical and overlap reports for `M=4` and `M=256`, with `M=384` used to
   directly exercise store-to-later-load overlap.
6. Documentation defining every interval, denominator, and distinction between
   logical concurrency and actual DMA descriptor execution.

## Out of Scope

- Performance CSR or MPM register changes.
- Functional changes to FSM scheduling, child queues, DMA priority, chunking,
  or completion semantics.
- Adding debug fields to synthesized command payloads.
- Using FSDB as the primary measurement source.
- Claiming DMA bandwidth concurrency from logical command overlap alone.

## Completion Criteria

The work is complete when the simulation-only instrumentation compiles out of
synthesis, all accounting invariants pass, the required workloads remain
numerically correct, and the final report can answer both of these questions
with raw cycle evidence:

1. Is tile double buffering hiding later-tile preload behind current-tile
   compute?
2. Is an output DRAM store's logical lifetime hidden behind later useful work,
   and when a later load is selected, is that overlap caused by safe
   store-pause/load-run scheduling rather than simultaneous descriptor use?

## Implementation and Execution Results

Status: implemented and verified on 2026-08-07.

The implementation uses `DBG_TRACE_GEMM_CMD_PERF` and compiles out under
`SYNTHESIS`. It adds no performance CSR and does not change functional command
scheduling. The structured-log parser is:

```text
tools/gemm_command_overlap_summary.py
```

The combined XRT-VCS report is:

```text
agent-tasks/gemm-command-overlap-trace/results/
  xrt_vcs_command_overlap_commands.csv
  xrt_vcs_command_overlap_pairs.csv
  xrt_vcs_command_overlap_dma.csv

```

### XRT-VCS results

All workloads used `N=32`, `K=128`, `QBLK=32`, `WTRANS=0`, and `QDIR=0`.
They ran through `ci/run_black.sh xrt-vcs-sim` with the established
`improve_th32_tcol32_hwexp_dcache_sxbar_f16_bigmem_w8` configuration. All
three numerical comparisons passed.

| M | Cycles | Commands | Max logical concurrency | Preload-next / compute | Store / next compute | Store / later load | Final store drain |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 4 | 273 | 22 | 4 | N/A | N/A | N/A | 37 |
| 256 | 1809 | 44 | 7 | 117 | 58 | 0 | 324 |
| 384 | 2527 | 66 | 8 | 121 for tile 0; 179 for tile 1 | 209 for tile 0; 58 for tile 1 | 181 for tile 0 | 324 |

Raw values are cycles. Every invocation reported
`emitted == issued == completed` and `incomplete=0`.

The primary `M=256` result shows that tile 1 preload is fully hidden behind
tile 0 compute: the measured intersection is 117 cycles, preload tail is zero,
and tile-ready slack is 488 cycles. Tile 0 output store overlaps tile 1 compute
for 58 cycles. Store-versus-later-load is correctly zero because this workload
has no tile 2.

The `M=384` control directly exercises the new path. Store 0 logically overlaps
the tile 2 load for 181 cycles. The associated DMA command record reports a
211-cycle store lifetime, 52 descriptor-active cycles, 148 paused cycles, two
chunks, and one four-cycle store-to-load switch. The mutually exclusive DMA
descriptor predicates remained asserted, so this is safe store-pause/load-run
scheduling rather than simultaneous load/store descriptor execution.

### Directed verification results

- Parser unit tests passed.
- Trace-enabled `gemm_ctrl` and `gemm_tmem_dma_ctrl` VCS suites passed.
- Deterministic uniform-vector `M=4`, `M=256`, and `M=384` node tests passed
  with tracing both enabled and disabled.
- Trace-on and trace-off job completion times matched exactly for every node
  workload, proving that the instrumentation does not perturb scheduling.
- The parser accepted 132 command records, 771 overlap records, and 30 DMA
  records from the final XRT-VCS runs.

The dirty branch's default nonuniform node-unit-test vectors have a separate
pre-existing lane/data-layout failure that also reproduces with tracing
disabled. It is not used as the acceptance baseline for this simulation-only
observability change; the full XRT-VCS application workloads above pass their
normal numerical comparison.
